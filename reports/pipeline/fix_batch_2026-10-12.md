# Pipeline fix batch, 2026-10-12: progress report

The decided-but-unbuilt items of the activation-extraction pipeline review, worked one at a time by a
single Opus agent for the Fable coordinator (Roger, 2026-10-12: one agent, in a sensible order, the
multi-model plan last, escalating to Fable and then to Roger).  The specification of every item is the
review record, [escalations.md](../code_review_2026-10-12/escalations.md): the P1-P5 reviewer sections
and "Decisions so far", where the walk-through's own labels P1-P8 name the items below.  The operating
document for the pipeline is [pipeline/README.md](../../pipeline/README.md); it is updated in the same
commit as each behaviour change.

**Terms.**  *The pipeline* is the five steps under [pipeline/](../../pipeline/): step 1 generates
responses ([1_generate.py](../../pipeline/1_generate.py)), step 2 extracts activations
([2_activations.py](../../pipeline/2_activations.py)), step 3 judges them
([3_judge.py](../../pipeline/3_judge.py)), step 4 averages the score-3 activations into one vector per
entity ([4_vectors.py](../../pipeline/4_vectors.py)) and step 5 makes the axis, mean default vector minus
mean entity vector ([5_axis.py](../../pipeline/5_axis.py)); [run_pipeline.sh](../../pipeline/run_pipeline.sh)
is the driver and [scan_missing_vectors.py](../../pipeline/scan_missing_vectors.py) the scanner that
classifies missing or corrupt vectors.  *Roger mode* generates the role x trait combinations, the
standalone traits (and roles) and the default; *christina mode* (the original paper's) generates the
standalone entities of one directory.  An *entity* is a role, a trait, a combination (`r_<role>__<trait>`,
`t_<role>__<trait>`) or `default`.  *8slot* is the current Qwen3-32B tree, slot 0 the body mean and slots
1-7 the header tokens.  *Platform paths* are the files whose uncommitted edits stop the gap-generation
session's paid runs (`PLATFORM_PATHS` in [runs.py](../../assistant_axis/gapgen/runs.py)); an edit to one
is committed on its own as soon as it is green.

Tests are run as `uv run pytest -q -p no:cacheprovider ...`.  "The pipeline set" is
[pipeline/tests/](../../pipeline/tests/) plus `test_atomic_io.py`, `test_axis.py`, `test_tmpfs.py`,
`test_generation*.py`, `test_judge_pricing.py`, `test_judge_extensions.py`, `test_spans.py` and
`test_conversation_encoder.py` under [assistant_axis/tests/](../../assistant_axis/tests/).  Its 8 errors
in every run are `test_generation.py`'s tokenizer tests, which need the Hugging Face cache the sandbox
does not allow; they are not looked into.

Baseline before any change: the pipeline set, **333 passed, 8 errors**.

## 1. P8, the small items

Order of work: 8.1, 8.2, 8.4 (committed first and on its own, at the coordinator's request, because
[atomic_io.py](../../assistant_axis/atomic_io.py) is a platform path), 8.6, 8.5, 8.3.

### 8.1 Step 1's exit status

[1_generate.py](../../pipeline/1_generate.py): `run_items` replaces the two item loops (worker and
single-worker).  An item that fails (an exception, no `instruction`, no responses) is logged and the run
goes on; after `MAX_CONSECUTIVE_FAILURES` (20) failures in a row it stops trying the rest (an engine
that died fails every later item fast).  `_report_failures` logs the tally and the failed names; any
failure makes the worker exit 1 (so `run_multi_worker` returns 1) and the single-worker `main` exit 1.
The module docstring states the exit status.

### 8.2 Goal-list names

`check_goal_list_files` runs before the grid is built: every role and trait the grid takes from the goal
lists (only the halves in use, so `--combos_only_t` does not need the r_ half's names) must have its
instruction file, or `GoalListError` stops the step (exit 1, nothing generated).  The message names each
missing file and, when an instruction file's `renamed_from` records the name (string, object or list),
the stem it became.  The grid size is logged against `goal_count x non_goal_count x 2` (x 1 for one
half): INFO when equal, a WARNING with the four list lengths when a list is shorter than its count.

### 8.4 `FileNotFoundError` is not transient (commit 47360a6d)

[atomic_io.py](../../assistant_axis/atomic_io.py): `NON_TRANSIENT_READ_ERRORS = (FileNotFoundError,)`,
re-raised on the first attempt by `_retry_read` (a parameter, `non_transient`, defaults to it).
`TRANSIENT_READ_ERRORS` itself is unchanged, since `FileNotFoundError` is an `OSError` and cannot leave
the tuple; an `OSError` with errno `ESTALE` is not a `FileNotFoundError` and is still retried (tested).
The nfs-io text of [AGENT_NOTES.md](../../AGENT_NOTES.md) (synced to
[nfs-io.md](../../.claude/rules/nfs-io.md)) and the README's read-retry bullet say so.  One caveat
written into the notes: over NFS a file another client has just created can be briefly invisible; no
pipeline reader depends on that (each reads what a listing or an earlier step of the same process
produced).

### 8.6 One tmpfs mirror implementation

[tmpfs.py](../../assistant_axis/tmpfs.py) is the only mirror code now:

- `setup_model_tmpfs_cache(..., method=)` with `MIRROR_METHODS = ("auto", "rsync", "cp")`;
  `resolve_mirror_method`: auto is rsync when on PATH, else cp.
- `_cp_mirror`: removes leftover `.<name>.partial.*` staging directories, copies with
  `shutil.copytree(symlinks=True)` (the hub's relative snapshot links stay links, as with `cp -r`) into
  `.<name>.partial.<pid>`, writes the marker inside, and renames into place; on a failed rename it uses
  a mirror another process completed meanwhile.  An existing directory without a valid marker is neither
  trusted nor deleted under cp (a process may be loading from it): the call returns None and the warning
  says to delete it or use rsync.
- rsync removes an old marker before a top-up, so a top-up killed half way leaves no marker.
- Both methods write the marker, which now records `method`.
- The mount is the parent of `tmpfs_hf_home` (it was `/dev/shm` whatever the target), checked for
  existence and measured for free space; this also made the whole call testable on a laptop.
- `_main` / `python assistant_axis/tmpfs.py mirror --model M --tmpfs-hf-home D --source-hf-home S
  --method X`: prints the new HF_HOME and exits 0, or exits 1 with nothing on stdout.  Standard library
  only, so the shell runs it as a file without importing the package.

[run_pipeline.sh](../../pipeline/run_pipeline.sh): `setup_tmpfs` keeps its `TMPDIR` and compile-cache
parts and calls the helper for the mirror (its own `cp -r`, size check and staging are gone);
`--tmpfs-method` (validated before anything runs).  A missing `/dev/shm` no longer skips the `TMPDIR`
part (which falls back to `/tmp` on its own); the mirror is skipped when its mount is missing.
[run_sweep.py](../../steering/run_sweep.py): `--tmpfs-method`, passed to the parent's pre-spawn mirror
and through the worker config to each worker's call.

### 8.5 Christina mode over traits gets a default

The driver's step 0 (generate, extract and average `default` once under `<output_dir>/default/`) is now a
function, `run_step0_default`, used by both modes.  In christina mode, when `--roles_dir` has no
`default.json` (a traits run), the default is generated from `DEFAULT_ROLE_DIR`
(`../data/roles/instructions`) with the christina settings (240 questions, no reduction, as the traits)
and its response, activation and vector are symlinked into the tree (`../default/<sub>/default.<ext>`),
so step 3 skips it, steps 2 and 4 find it done, and step 5 and the scan see it.  No default anywhere
stops the run before step 1.  A roles run is unchanged.

### 8.3 Lazy package `__init__`; no stand-in package; early exits

- [assistant_axis/__init__.py](../../assistant_axis/__init__.py): PEP 562 `__getattr__` over a
  name-to-submodule table; `__all__` is the same 58 names in the same order (checked against HEAD); the
  submodules the eager file imported (`models`, `axis`, `generation`, `steering`, `pca`,
  `plot_metadata`, `plot_palette`, `pair_list_cohort`, `judge_batch`) stay reachable as attributes;
  `__dir__` lists them.  The `entity_id` names are imported eagerly: the module is standard library only,
  and its function `entity_id` shares the module's name, so a lazy lookup would leave the module bound
  after `import assistant_axis.entity_id` and `from assistant_axis import entity_id` would return it.
  Measured: `import assistant_axis.entity_id` 1.44 s and 2,093 modules before, 0.012 s and 77 after.
- [3_judge.py](../../pipeline/3_judge.py): the stand-in package is gone; plain imports, keeping the
  `_judge_mod`, `_pricing_mod`, `_openai_batch`, `_atomic_io` aliases the tests use.  The docstring of
  [openai_batch.py](../../assistant_axis/openai_batch.py) no longer says step 3 loads it without the
  package.
- The other sites the review listed: [compute_combo_marginals.py](../../results_analysis/compute_combo_marginals.py)
  and canonical_angles [data.py](../../results_analysis/canonical_angles/data.py) /
  [core.py](../../results_analysis/canonical_angles/core.py) have **no** stand-in workaround: they do
  not import `assistant_axis` at all, and their "standalone" names (`_standalone_dir`,
  `_standalone_etype`) mean standalone entities.  The P1 reviewer's count of five was a grep false
  positive; nothing to retire there.  [test_gapgen_calibrate.py](../../assistant_axis/tests/test_gapgen_calibrate.py)
  loads a CLI script by path (the usual way to test a script that is not in a package), which is not a
  stand-in package either; by the coordinator's instruction it is left to the gap-generation session in
  any case.
- Steps 2 and 4 decide whether there is work before importing torch (the recorded slow start is that
  import from the network volume).  Each script defines its parser and a standard-library check above
  the heavy imports, and runs the check only when executed as a script, so the tests that import the
  module are unaffected: step 2's `pending_response_files` (also used by both of its modes, replacing two
  copies, and logging one skip line instead of one per entity), step 4's `needs_work` / `nothing_to_do`
  (`--overwrite` is always work; an empty activations directory is left to `main`'s error).
