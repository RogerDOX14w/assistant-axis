# M3 cover audit: are these really covered? For Roger's marks (2026-10-09)

Written for Roger.  The novelty scorer (M3) decided that each word below is already covered by an existing trait, so it never reached review.  This file checks that on real generator output: 100 of the 173 covers from the three pilots of 2026-10-08 (the TDA census, Roget, and the WordNet stream) that were not exact label matches.  Question 5 in [QUESTIONS.md](./QUESTIONS.md) says why; the plan of record for M3 is in [coding_plan_platform.md](./coding_plan_platform.md).

**How to mark.**  For each row, read the candidate's gloss (what the word was taken to mean) and the covering trait's description, and put one of these in the last column:

- **C**: covered.  The existing trait already does this job; you would not add the word.
- **N**: new.  You would want this as a trait of its own (a real gap that M3 hid).
- **?**: unsure, or the gloss misreads the word (add a few words if you like).

The rows are shuffled and do not show how the scores came out, so the marks are not anchored; the key that says which group each row came from is in [key.json](../../data/candidates/novelty/m3_cover_audit/key.json), read after marking.  Hand-read marks are fine: I parse them myself.
